# 同步架构

coding-cli 使用同步 Anthropic SDK（`Anthropic` 而非 `AsyncAnthropic`），所有模块（LLM 调用、工具执行、记忆管理）均为同步实现。

## 背景

异步（`AsyncAnthropic` + `async def execute`）是合理选项，尤其在未来需要并发执行多个 sub-agent 时。

## 决定

使用同步架构。理由：

1. **CLI 工具无并发需求**——单用户、单线程、顺序执行，async 是凭空背上的复杂度
2. **认知预算集中在模块串联**——当前核心目标是学会"循环怎么串"，不是学会异步编程
3. **subprocess 在同步下行为自然**——阻塞等待是正确行为，不存在"冻住事件循环"的问题
4. **未来迁移成本低**——需要翻成 async 的只有 `llm.chat` 和 `registry.run` 两个咽喉函数，架构已把迁移从"大换血"降成"小手术"
